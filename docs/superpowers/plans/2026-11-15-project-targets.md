# Project-local Targets Implementation Plan

> **For agentic workers:** Use the briefed skilletor-worker for implementation; the coordinating main agent reviews independently. The maintainer requested autonomous execution without further approval questions. No commits or publication are authorized.

**Goal:** Stop machine-wide harness detection from installing Codex assets into Claude-only projects.

**Architecture:** Retain machine selection and user-scope behavior; add read-only project evidence at the existing target-selection seam. Both engines consume the same deterministic policy, independent of invoking harness. Ambiguous multi-harness projects are preserved, not emptied.

**Tech Stack:** Erasable TypeScript, Node node:test, Perl 5.40-compatible port, shared conformance fixtures.

**Spec:** `docs/superpowers/specs/2026-11-15-project-targets-design.md` (k229).

## Global Constraints

- User `targets` limits the available machine harnesses; it does not force each project to use all of them.
- Local project `targets` overrides committed project `targets`; neither can broaden machine targets.
- No new runtime dependency, config schema, paid eval, public action or real-home sync.
- Preserve existing k200/k220 work and the separate original checkout's k178 work.
- Reserve conformance cases 130–139 for k178 and 140 for k200; choose free cases from 141 onward.
- No own/generated artifact may create a permanent harness opt-in.

## Review Focus

- Repeated sync must not change target inference after writing settings, skills or ignore blocks.
- Alternating Claude/Codex hook invocation must not toggle/delete targets.
- Missing evidence in a multi-harness project preserves managed and foreign project files.
- Explicit global both plus implicit Claude-only project must produce no Codex project artifacts.
- A user-owned file or linked root must not be deleted as part of target migration.
